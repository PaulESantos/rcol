1 Introducción y Arquitectura General

El paquete rcol (R Client for the Catalogue of Life / ChecklistBank API) proporciona un acceso idiomático y de alto rendimiento a la API REST de ChecklistBank (https://api.checklistbank.org) y a las publicaciones mensuales y anuales del Catalogue of Life (COL).

El paquete exporta 46 funciones públicas organizadas en dos capas o familias principales de funciones:

  1. Familia clb_*() (Bajo Nivel / Universal):
    • Requieren o aceptan explícitamente el parámetro dataset (dataset = "3LXR", dataset = "COL25", dataset = 2099, etc.).
    • Permiten consultar cualquier conjunto de datos publicado en ChecklistBank o versiones históricas del COL.
  2. Familia col_*() (Atajos / Pinned Version):
    • Omiten el argumento dataset.
    • Utilizan internamente la función col_key() para fijar la versión extendida del Catalogue of Life en la sesión activa ("3LXR").
    • Garantizan consistencia en análisis científicos al fijar la clave numérica en la sesión.

1.1 Conceptos Clave y Estandarización de Funciones

1.1.1 1. Diferencia entre clb_match() y col_match()

  • clb_match(): Es el motor base de bajo nivel del sistema de coincidencia de nombres científicos. Consulta directamente ChecklistBank y permite especificar cualquier dataset (versiones históricas del COL, catálogos locales, etc.).
  • col_match(): Es la función atajo de alto nivel predeterminada para trabajar con el Catalogue of Life. Es un wrapper de clb_match() que utiliza automáticamente la clave del release extendido de COL fijado en la sesión activa (col_key()).

1.1.2 2. col_match() vs. col_check_name() / col_resolve_name()

  • col_match(): Recupera la información taxonómica cruda completa directamente desde la API (16 columnas, incluyendo la lista anidada classification, metadatos nomenclaturales, etc.). Es ideal para análisis exhaustivos.
  • col_check_name() / col_resolve_name(): Organizan y simplifican los resultados en un tibble limpio de 9 columnas esenciales. Muestran de forma rápida si el nombre es aceptado o sinónimo, el nombre aceptado válido, la autoría y su ID.

1.1.3 3. Estandarización de col_classification() y clb_classification()

  • col_classification() y clb_classification() se han unificado para permitir:
    • Búsqueda por ID de taxón (ej. "4V8GC").
    • Búsqueda por nombre científico directo (ej. "Schinus molle").
    • Consulta desde un dataframe de match (col_check_name() o col_match()).
    • Soporte del parámetro wide = TRUE / wide = FALSE para obtener la jerarquía desanidada en formato Ancho o Largo (manteniendo col_extract_classification() como alias totalmente compatible).

1.1.4 4. Flexibilidad de Entradas en el Módulo de Relaciones

Todas las funciones del módulo de relaciones (col_synonyms(), col_vernacular(), col_distribution(), col_classification(), col_usage(), col_usage_metrics()) aceptan indistintamente cualquiera de los siguientes tres tipos de entrada: 1. Un nombre científico directo (ej. "Werneria nubigena", "Panthera leo"). 2. Un ID alfanumérico del COL (ej. "B87CR", "4CGXP"). 3. El dataframe completo devuelto por col_check_name() o col_match().

3 Especificación de Funciones por Módulo

3.1 1. Configuración de Entorno y Pinning de Versión

3.1.1 clb_base_url()

  • Descripción: Obtiene la URL base de la API de ChecklistBank.
  • Entradas (Inputs): Ninguna (lee la variable de entorno CLB_BASE_URL o usa "https://api.checklistbank.org").
  • Salida (Output): Vector de caracteres de longitud 1 (character).

3.1.2 col_key(refresh = FALSE)

  • Descripción: Resuelve la clave numérica de la versión extendida de COL ("3LXR") y la almacena en caché de sesión.
  • Entradas (Inputs): refresh (logical, por defecto FALSE).
  • Salida (Output): Vector entero (integer key, ej. 3).

3.1.3 col_refresh()

  • Descripción: Fuerza la re-resolución y actualización de la versión del COL fijada en sesión.
  • Entradas (Inputs): Ninguna.
  • Salida (Output): Vector entero (integer), de forma invisible.

3.1.4 clb_col_release(cadence = c("monthly", "annual"), extended = FALSE)

  • Descripción: Obtiene el alias estándar del release de COL (ej. "3LR", "3LXR", "COL25").
  • Entradas (Inputs): cadence ("monthly" o "annual"), extended (logical).
  • Salida (Output): Vector de caracteres (character, ej. "3LXR").

3.1.5 clb_col_releases(project = 3L, ...)

  • Descripción: Lista todas las versiones históricas anuales y mensuales derivadas del proyecto COL (project = 3).
  • Entradas (Inputs): project (integer), parámetros adicionales.
  • Salida (Output): tibble con columnas key, alias, title, issued, version, etc.

3.2 2. Coincidencia Taxonómica (Name Matching) y Verificación

3.2.1 clb_resolve_name(name, ...) / clb_check_name(name, ...) / col_resolve_name(name, ...) / col_check_name(name, ...)

  • Descripción: Resolución limpia y simplificada de alta legibilidad para verificar directamente el nombre válido/aceptado de una especie o lista de especies. Elimina la complejidad de metadatos crudos y listas anidadas de col_match().
  • Entradas (Inputs): name (cadena de texto simple o vector de caracteres).
  • Salida (Output): tibble compacto con 9 columnas esenciales en orden de lectura: queried_name, matched_name, status, accepted_name, accepted_authorship, accepted_rank, accepted_id, match, match_type.
  • Dependencias: Llama internamente a col_match() para 1 especie o col_match_checklist() para vectores de especies.

3.2.2 clb_match(name, authorship = NULL, rank = NULL, code = NULL, dataset = "3LXR", server = NULL, .raw = FALSE) / col_match(...)

  • Descripción: Busca la única mejor coincidencia para un nombre científico en un dataset.
  • Entradas (Inputs): name (character), authorship, rank, code, dataset, server, .raw.
  • Salida (Output): tibble de 1 fila × 16 columnas (match, match_type, usage_id, name, authorship, rank, status, accepted_id, accepted_name, accepted_authorship, code, label, parent_id, names_index_id, names_index_match_type, classification). Resuelve automáticamente el taxón aceptado (accepted_*) tanto para nombres aceptados como para sinónimos.

3.2.3 clb_match_verbose(...) / col_match_verbose(...)

  • Descripción: Retorna la coincidencia principal junto con todos los homónimos o candidatos alternativos.
  • Salida (Output): tibble de N filas con una columna lógica primary (TRUE para la coincidencia elegida, FALSE para las alternativas).

3.2.4 clb_match_checklist(data, name = "name", authorship = "authorship", rank = "rank", code = "code", dataset = "3LXR", server = NULL, max_active = 5L) / col_match_checklist(...)

  • Descripción: Realiza el emparejamiento masivo de una lista o data frame de nombres usando solicitudes HTTP en paralelo (httr2::req_perform_parallel).
  • Salida (Output): tibble con las columnas originales de entrada prefijadas con verbatim_* seguidas de las columnas de resultado de match.

3.3 3. Extracción de Clasificación Jerárquica

3.3.1 clb_extract_classification(data, wide = FALSE, dataset = "3LXR", ...) / col_extract_classification(data, wide = FALSE, ...)

  • Descripción: Desanida y extrae la jerarquía taxonómica completa a una tabla limpia en formato Largo o Ancho (wide = TRUE). Admite vectores de nombres o dataframes devueltos por col_check_name() o col_match().
  • Entradas (Inputs): data (vector de caracteres o dataframe de match), wide (logical, FALSE para formato largo, TRUE para formato ancho con columnas kingdom, phylum, class, order, family, genus, species).
  • Salida (Output): tibble estructurado con la clasificación completa.

3.4 4. Consultas de Usos Taxonómicos y Búsqueda Libre

3.4.1 clb_usage(id, dataset = "3LXR", .raw = FALSE) / col_usage(id, .raw = FALSE)

  • Descripción: Obtiene los detalles completos de un uso taxonómico (especie o sinónimo) por su ID único.
  • Salida (Output): tibble de 1 fila (id, scientific_name, authorship, rank, status, label, parent_id, extinct, name).

3.4.2 clb_usage_search(q = NULL, dataset = "3LXR", rank = NULL, status = NULL, ..., limit = 50L, max = limit) / col_usage_search(...)

  • Aliases: clb_search(), col_search().
  • Descripción: Búsqueda por texto libre de usos taxonómicos en un dataset.
  • Salida (Output): Objeto S3 clb con $data (tibble de resultados) y $meta (total de registros).

3.4.3 clb_suggest(q, dataset = "3LXR", ..., .raw = FALSE) / col_suggest(...)

  • Descripción: Autocompletado rápido de nombres por prefijo.
  • Salida (Output): tibble con sugerencias rápidas (suggestion, usageId, rank, status).

3.5 5. Relaciones Taxonómicas: Jerarquía, Sinónimos, Nombres Comunes, Distribución y Métricas

3.5.1 clb_classification(id, dataset = "3LXR", wide = FALSE, .raw = FALSE) / col_classification(...)

  • Descripción: Retorna la cadena ordenada de ancestros de un taxón por su nombre científico directo, ID o dataframe de match.
  • Salida (Output): tibble de ancestros (1 fila por rango) con columnas limpias: id, scientific_name, authorship, rank, full_name (sin código HTML de cursiva).

3.5.2 clb_synonyms(id, dataset = "3LXR", full = FALSE, .raw = FALSE) / col_synonyms(id, full = FALSE, .raw = FALSE)

  • Descripción: Obtiene todos los sinónimos asociados a un taxón. Acepta un nombre científico directo, un ID de taxón, o un dataframe devuelto por col_check_name() o col_match(). Por defecto retorna únicamente las 6 columnas esenciales (accepted_name, scientific_name, authorship, synonym_type, rank, full_name).
  • Entradas (Inputs): id (nombre científico, ID o dataframe de match), full (logical, por defecto FALSE).
  • Salida (Output): tibble limpio con 6 columnas esenciales (o metadatos secundarios completos si full = TRUE).

3.5.3 clb_vernacular(id = NULL, dataset = "3LXR", q = NULL, lang = NULL, ..., limit = 50L, max = limit, full = FALSE) / col_vernacular(...)

  • Descripción: Obtiene los nombres comunes o vernáculos por nombre científico directo, vector de múltiples especies, ID de taxón o dataframe de match.
  • Salida (Output): tibble depurado que preserva la asociación de especies mediante la columna scientific_name (scientific_name, name, language, latin, country, area, remarks). Excluye referenceId y metadatos no esenciales por defecto.

3.5.4 clb_distribution(id, dataset = "3LXR", tidy = TRUE, full = FALSE, .raw = FALSE) / col_distribution(...)

  • Descripción: Obtiene la distribución geográfica oficial (países y regiones) para un taxón por su nombre científico directo, vector de especies, ID o dataframe de match.
  • Entradas (Inputs): id (cadena, vector o dataframe de match), tidy (logical, por defecto TRUE, desglosa regiones delimitadas por punto y coma en filas individuales), full (logical, por defecto FALSE).
  • Salida (Output): tibble depurado con la columna area (y scientific_name cuando se consultan múltiples especies).

3.5.5 clb_usage_metrics(id, dataset = "3LXR", .raw = FALSE) / col_usage_metrics(...)

  • Descripción: Obtiene métricas del subárbol de un taxón (conteo de especies descendientes, desglose por rango).
  • Salida (Output): tibble de 1 fila con métricas y mapa de recuentos.

3.6 6. Navegación del Árbol Taxonómico

3.6.1 clb_tree(dataset = "3LXR", id = NULL, extinct = TRUE, ..., limit = 100L, max = limit) / col_tree(...)

  • Descripción: Retorna los nodos raíz del árbol taxonómico o los hijos directos de un nodo.
  • Salida (Output): tibble de nodos del árbol (id, name, rank, childCount).

3.6.2 clb_children(id, dataset = "3LXR", extinct = TRUE, ..., limit = 100L, max = limit) / col_children(...)

  • Descripción: Retorna los taxones hijos inmediatos de un taxón padre.
  • Salida (Output): tibble de taxones hijos.

3.7 7. Catálogo de Datasets

3.7.1 clb_dataset_search(q = NULL, ...)

  • Descripción: Busca conjuntos de datos dentro de ChecklistBank.
  • Salida (Output): Objeto S3 clb de datasets.

3.7.2 clb_dataset(key, .raw = FALSE) / col_dataset(...)

  • Descripción: Obtiene los metadatos completos de un conjunto de datos por su clave o alias.
  • Salida (Output): tibble de 1 fila con metadatos del dataset (title, version, publisher, etc.).

3.7.3 clb_dataset_metrics(key, .raw = FALSE) / col_dataset_metrics(...)

  • Descripción: Métricas globales de un dataset (total de taxones, sinónimos, distribución de rangos).
  • Salida (Output): tibble de métricas del dataset.

3.8 8. Parsers Nomenclaturales y de Valores

3.8.1 clb_parse_name(names, .raw = FALSE)

  • Descripción: Parsea nombres científicos en sus componentes atómicos (epíteto específico, autoría, género, subgénero).
  • Salida (Output): tibble estructurado del parser taxonómico.

3.8.2 clb_parsers()

  • Descripción: Lista todos los tipos de parsers de valores controlados disponibles en ChecklistBank.
  • Salida (Output): Vector de caracteres con los nombres de los parsers.

3.8.3 clb_parse(type, values, .raw = FALSE)

  • Descripción: Parsea valores utilizando un parser controlado específico (ej. rank, nomStatus).
  • Salida (Output): tibble con los valores mapeados al estándar.

4 Ejemplo Completo de Flujo de Trabajo en R

library(rcol)
library(dplyr)

# 1. Fijar o verificar la versión activa del Catalogue of Life
col_key()

# 2. Verificación limpia de nombres válidos/aceptados (col_check_name)
especies <- c("Werneria nubigena", "Panthera leo", "Schinus molle")
resumen_nombres <- col_check_name(especies)
print(resumen_nombres)

# 3. Extracción de clasificación taxonómica jerárquica en formato Ancho
clasif_wide <- col_extract_classification(resumen_nombres, wide = TRUE)
print(clasif_wide)

# 4. Obtención de sinónimos taxonómicos pasando directamente el dataframe de match
sinonimos_werneria <- col_synonyms(resumen_nombres[1, ])
print(sinonimos_werneria)

# 5. Obtención de nombres vernáculos depurados
nombres_comunes_leo <- col_vernacular(resumen_nombres[2, ])
print(nombres_comunes_leo)

# 6. Obtención de distribución geográfica en formato tidy (columna area)
distribucion_schinus <- col_distribution(resumen_nombres[3, ])
print(distribucion_schinus)

# 7. Parsing anatómico de nombres científicos
parsed <- clb_parse_name("Abies alba Mill. var. alpina")
print(parsed)
